## Where AI helped

Codex helped accelerate boilerplate and repetitive implementation across models, configuration, persistence, workflow plumbing, and the demo interface. It also helped generate tests and edge cases, review consistency across modules, and draft documentation. These contributions let me spend more time evaluating architecture, authorization boundaries, and behavior. The repository shows the resulting implementation and tests; it does not quantify time saved or isolate every AI contribution.

## Where AI fell short

AI initially leaned toward making department eligibility rigid enough that an employee outside the configured department would simply be rejected. I challenged that assumption using a Product Manager requesting GitHub Write access as the concrete case. A request can be outside the normal eligibility policy without automatically being illegitimate. I chose a controlled exception-review path: the system does not authorize the access itself, but preserves the request and routes it to the configured reviewer for human judgment.

Deterministic policy remains the normal authorization boundary. The system does not invent eligibility, legitimate exceptions are not silently discarded, and a human owns the consequential exception decision. The implemented exception requires a configured policy and at most one authorized reviewer. A request with no matching policy instead enters manual investigation and cannot be approved or provisioned through that state.

Generated code and documentation still required manual review, execution, and correction rather than acceptance based only on Codex output. The acceptance audit records two behavior corrections: preserving valid policy-less requests for manual review and delivering actionable mock IT notifications after revocation failure. It also records the incorrect test expectation for an explicit reject policy and its correction. These are verified project corrections, but the evidence does not identify who authored each original defect or correction; they should not be presented as individually proven Codex mistakes.

Documentation also needed consistency review. The stale README statements identified in the table show that accumulated documentation can lag behind working code. They remain review items, not corrections performed by this log-writing task.
